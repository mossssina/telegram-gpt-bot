# PROJECTS_REGISTRY.md — Реестр клиентских проектов

## Где хранится реестр

```
config/projects.json
```

Это единственный источник списка проектов для сотрудников.
Заполненные брифы заказчиков **автоматически** добавляют проект в реестр,
но сотрудники видят только те проекты, которые находятся в реестре.

---

## Структура записи

```json
{
  "taiga": {
    "title": "Taiga Architects",
    "folder": "client_projects/taiga",
    "memory_file": "client_projects/taiga/memory.md",
    "brief_file": "client_projects/taiga/brief.md",
    "is_active": true
  }
}
```

| Поле | Описание |
|---|---|
| `title` | Название, которое видят сотрудники в меню |
| `folder` | Путь к папке проекта |
| `memory_file` | Путь к файлу памяти (контекст для GPT) |
| `brief_file` | Путь к файлу брифа |
| `chat_context_file` | Путь к сырому журналу клиентского чата (опционально, по умолчанию `<folder>/chat_context.md`) |
| `staff_dialog_file` | Путь к журналу диалогов сотрудников с ботом по проекту (опционально, по умолчанию `<folder>/staff_dialog.md`) |
| `is_active` | `true` — проект виден в меню, `false` — скрыт |

---

## Как добавить проект вручную

Откройте `config/projects.json` и добавьте запись:

```json
{
  "taiga": {
    "title": "Taiga Architects",
    "folder": "client_projects/taiga",
    "memory_file": "client_projects/taiga/memory.md",
    "brief_file": "client_projects/taiga/brief.md",
    "is_active": true
  }
}
```

Если папки `client_projects/taiga/` нет — создайте её вручную.
`brief.md` и `memory.md` можно добавить позже — бот не упадёт, если файлы отсутствуют.

---

## Как скрыть проект

Установите `"is_active": false`:

```json
{
  "old_project": {
    "title": "Старый проект",
    ...
    "is_active": false
  }
}
```

Проект останется в файле, но не будет отображаться в меню сотрудников.

---

## Как работает связь

```
config/projects.json
    ↓
  slug (ключ записи)
    ↓
client_projects/<slug>/
    ├── brief.md     ← показывается по кнопке «Посмотреть бриф»
    └── memory.md    ← передаётся GPT как контекст проекта
```

---

## Почему список берётся из реестра, а не из папок

Раньше список проектов формировался из папок `client_projects/`, в которых
есть `brief.json`. Это значило, что проект появлялся только после заполнения
брифа заказчиком.

Теперь реестр (`config/projects.json`) — единственный источник:
- сотрудники видят проекты, которые им нужно вести, даже без брифа;
- новые брифы автоматически добавляют проект в реестр;
- проект можно добавить вручную с нужными путями к файлам;
- неактивные проекты скрыты (`is_active: false`), но данные сохранены.

---

## Автодобавление при заполнении брифа

Когда заказчик заполняет бриф через бота:
1. Создаётся папка `client_projects/<slug>/`
2. Сохраняются `brief.json`, `brief.md`, `memory.md`
3. Если проекта нет в реестре — он добавляется автоматически

Если проект уже есть в реестре — дублирования не происходит.
