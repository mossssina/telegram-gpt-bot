# CHAT_REGISTRY.md — Реестр рабочих чатов

Бот умеет регистрировать групповые Telegram-чаты и топики, и отправлять в них сообщения.

---

## Где хранится список чатов

```
config/chats.json
```

Формат (с поддержкой топиков):

```json
{
  "team": {
    "title": "Общий чат команды",
    "chat_id": "-1001111111111",
    "type": "supergroup",
    "thread_id": null
  },
  "content_topic": {
    "title": "Общий чат команды / topic 15",
    "chat_id": "-1001111111111",
    "type": "supergroup",
    "thread_id": 15
  }
}
```

`thread_id: null` — сообщение идёт в общий чат.  
`thread_id: 15` — сообщение идёт в конкретный топик.

Если файл отсутствует — бот создаёт пустой `{}` автоматически при первой регистрации.

---

## Шаг 1. Добавить бота в группу

Откройте нужный Telegram-чат → Добавить участников → найдите бота по имени.
Убедитесь, что боту разрешено отправлять сообщения.

---

## Шаг 2. Узнать chat_id и thread_id

Напишите прямо в групповом чате (или внутри нужного топика):

```
/chat_id
```

Бот ответит:

```
Chat ID:
-1001234567890

Thread ID:
None

Название чата:
Общий чат команды

Тип чата:
supergroup
```

Если команда написана внутри топика, `Thread ID` будет числом (например, `15`).  
Если в обычном чате — `Thread ID` будет `None`.

Команда доступна только сотрудникам.

---

## Шаг 3. Зарегистрировать обычный чат

Напишите в общем чате группы (не внутри топика):

```
/register_chat team
```

Бот сохранит `thread_id: null` — сообщения будут идти в общий чат.

---

## Поддержка топиков Telegram

### Как зарегистрировать топик

1. Добавьте бота в группу с включёнными темами (Topics).
2. Зайдите внутрь нужного топика.
3. Проверьте Thread ID:

```
/chat_id
```

Убедитесь, что `Thread ID` — число, не `None`.

4. Зарегистрируйте топик:

```
/register_chat content_topic
```

Бот ответит:

```
Зарегистрировано.

Слаг: content_topic
Название: Общий чат команды / topic 15
Chat ID: -1001234567890
Thread ID: 15
```

### Как отправить тест в топик

```
/send_test_to_chat content_topic
```

Тестовое сообщение придёт именно в топик `content_topic`, а не в общий чат.

### Несколько топиков одного чата

Один и тот же `chat_id` может использоваться с разными slug и разными `thread_id`:

```json
{
  "team": {
    "chat_id": "-1001111111111",
    "thread_id": null
  },
  "content_topic": {
    "chat_id": "-1001111111111",
    "thread_id": 15
  },
  "finance_topic": {
    "chat_id": "-1001111111111",
    "thread_id": 22
  }
}
```

---

## Шаг 4. Посмотреть список чатов и топиков

В личном чате с ботом:

```
/chats
```

Бот покажет список кнопками. По нажатию — детали: название, Chat ID, тип, Thread ID.

---

## Шаг 5. Отправить тестовое сообщение

```
/send_test_to_chat team
```

Бот отправит в нужное место и сообщит об успехе или ошибке.

---

## Автоматические уведомления

После заполнения брифа заказчиком бот отправляет уведомление в slug `team`.
Если `team` зарегистрирован как топик — уведомление придёт в топик.
Если `team` не зарегистрирован — бот пропускает отправку.

---

## Что делать, если бот молчит в топике

1. Проверьте, что бот добавлен в группу.
2. Проверьте права: бот должен иметь право отправлять сообщения в топики.
3. Убедитесь, что `/chat_id` написан внутри нужного топика (Thread ID не None).
4. Проверьте `config/chats.json` — `thread_id` должен совпадать.
5. Посмотрите логи в Terminal — там выводится ошибка `[CHAT SEND ERROR]`.

---

## Как удалить запись из реестра

Вручную отредактируйте `config/chats.json` — удалите нужную запись.

---

## Доступ

Все команды реестра — только для сотрудников (STAFF_USERS из .env).  
Заказчики не видят `/chat_id`, `/register_chat`, `/chats`, `/send_test_to_chat`.
